## Deviations from the issue, each with the reason

- **`ca-certificates` is a layer-0 package.** Not in the issue's table. Without it curl fails at TLS setup (`curl: (77) error setting certificate file`) before anything is fetched. The README names it.
- **The installer does not run `mise install` in shiv's clone** (the issue's constraint 3 says it does). Its verification step reports "shiv installed but verification failed" and exits 0. shiv's own tools install on the first `shiv` command instead.
- **That first command fails on a clean machine, every time, without `MISE_JOBS=1`.** Two of shiv's tools (`shiv:codebase@0.4`, `shiv:readme@latest`) are installed side by side by mise, and the two nested clones race — `fatal: shallow file has changed since we read it`, `Unable to read current working directory` — the shape of [vfox-shiv#22](https://github.com/KnickKnackLabs/vfox-shiv/issues/22). Measured twice on `debian:stable-slim`: 2/2 failures plain, 1/1 pass with `MISE_JOBS=1`. The README's recipe carries `MISE_JOBS=1 shiv install house` with the reason, and the job sets it. This is the finding W8 exists to make; it is shiv's to fix, not this repo's.
- **The source-file check follows how vfox-shiv actually resolves.** `hooks/backend_install.lua:168-183` reads `$SHIV_SOURCES_DIR` (default `~/.config/shiv/sources/*.json`) and then falls back to the *backend's own* clone (`$VFOX_SHIV_PATH`, else `$MISE_DATA_DIR/shiv-backend/shiv`, else `~/.local/share/mise/shiv-backend/shiv`), whose `sources.json` it re-syncs from the network at install time. So `doctor` checks source files, then the backend clone's index, then the CLI clone's (`$SHIV_INSTALL_PATH`, the installer's variable). When indexes exist and none names the package: `fail`, with `<sources dir>/<pkg>.json` as the fix. When no index is on the machine yet: `warn`, not `fail` — the backend will fetch the KnickKnackLabs index on first install, so a `fail` there would be wrong for every package in it. A stale clone that predates a newly added package would still `fail`; the fix printed works in that case too.
- **The bash floor reads `bash --version` of the first `bash` on `PATH`**, not `BASH_VERSINFO`. Same binary — `#!/usr/bin/env bash` is what runs every task — and it is testable through a fake.
- **`house doctor` in the job runs on a house whose markers have been answered.** A fresh house fails `doctor` by design, so `healthy` is the assertion the job makes.
- **`GITHUB_TOKEN: ${{ github.token }}` on the job**, for mise's GitHub API calls (the aqua and github backends behind bats, gum, uv). It is the job's read-only token, and it is visible to the piped installers, which is worth knowing.
- **`doctor` prints `ok` when the recorded version is the running one**; the issue specified only the two `note` cases.
- **`test/doctor.bats:112`** now appends `$HOME/.local/bin` to `PATH` for the "quiet" test, so "everything present" is stated by the test rather than assumed of the machine.
